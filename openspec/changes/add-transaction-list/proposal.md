## Why

The dashboard answers "on what did I spend?" (category cards) and "on which days?" (calendar), but not "what did I enter, in order?". Checking whether the supermarket from yesterday is already in, or reading back what the bot just logged, means opening category cards one by one, and income and savings live in other panels. Brian wants one place that lists, newest first, everything the user entered in the cycle.

## What Changes

- **A "Movimientos" card** below the category cards (after "Añadir categoría"), in the main column. It lists the cycle's **user-entered** movements only: expenses that are not tied to a recurring definition, income entries that are not recurring, and savings deposits and withdrawals. Recurring charges and recurring income (generated by the cron or projected) never appear, pending or taken.
- **Grouped by day**, newest first, with a day heading ("Hoy", "Ayer", "sáb 10 oct"). Each row shows what it is (category dot and name, "Ingreso", "Depósito" / "Retiro"), its description and its amount; income and savings carry a sign.
- **A segmented filter**: Todo / Gastos / Ingresos / Ahorro, on the existing segment track.
- **"Mostrar más"**: the first 10 rows at every width; each press reveals the same number again; once everything is shown and there was more than one page, "Mostrar menos" folds back to the first page. Filter and cycle changes start again from the first page.
- **Open at `lg`, folded below `lg`**, by default, with the same header disclosure as the category cards. Category cards, in turn, start folded at every width (Brian, 2026-10-12): at `lg` the open "Movimientos" card is the only expanded list on load.
- **Rows act like everywhere else**: tapping an expense or income row opens its sheet for editing; every row swipes to delete with undo (savings rows have no edit sheet yet, so they only swipe).
- **Sidebar entry** at `lg`: "Movimientos" joins the section list after the categories and follows the scroll-spy.
- **No totals in the list**: neither the card, nor a day, nor a filter states a sum, so the list never competes with the expense total (which includes recurring charges it does not show).
- Text search is out of scope for this change.

## Capabilities

### New Capabilities

- `transaction-list`: the "Movimientos" card. Which rows it holds, day grouping and order, filter, paging, default open state per viewport, row actions, sidebar entry, empty states, motion and accessibility.

### Modified Capabilities

- `dashboard-ui`: *Expense cards group each expense exactly once*. Every expense still sits in exactly one category card, and the movements list is named as the one place that lists user-entered expenses again (chronologically, mixed with income and savings, with no expense total). It is not a "variable expenses" card.

## Impact

- New pure function in `lib/data/` (`userMovements`: merge, filter, sort and group by local day, with `node:test` cases).
- New `components/organisms/movements-card.tsx` and a row molecule (`movement-row.tsx`); reuses `Collapsible`, `ExpandChevron`, `CategoryDot`, `Money`, `SwipeToDelete`, `.segment-track` / `.segment-thumb`.
- `components/templates/dashboard-template.tsx`: mount under the category list, open state per viewport, row handlers (existing `openEditSheet`, `openIncomeEditSheet`, `handleDelete*`), sidebar entry and scroll-spy id, `inert` during reorder mode.
- `messages/es.json`, `messages/en.json`: a new `movimientos` namespace.
- New Playwright spec `tests/movements.spec.js` on `/demo` (390px and 1280px, both themes, reduced motion, axe).
- No data access, no migration: the dashboard already receives every row the list needs for the shown cycle. Works the same on `/demo` and `/dashboard`.
